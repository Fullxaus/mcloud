# Практическая работа: Docker на Windows

Все материалы работы лежат в каталоге **`docs/docker-practice/`** в корне Gradle-проекта `mcloud` — этот каталог открывается в **IntelliJ IDEA** вместе с проектом.

Среда: **Windows 10/11**, **Docker Desktop**, движок в режиме **WSL 2** (`Context: desktop-linux`). Образы **alpine**, **ubuntu** и **busybox** намеренно **не загружались** (задание выполняется только в рамках установки на Windows и исследования `hello-world`).

## Ответы на вопросы

### 1. Какая версия Docker установлена на вашей системе?

**Клиент и Engine:** 29.2.0 (сборка клиента `0b9d198`, Engine `9c62384`). **Docker Desktop:** 4.60.1 (218372). Подробности — в `docker-version.txt`.

### 2. Сколько слоёв в образе hello-world?

В `docker inspect` у `RootFS` указан **один** слой (`Layers` содержит один SHA256). В `docker history` видны шаги сборки (например, `COPY` и `CMD`); итоговый образ для запуска соответствует одному корневому слою файловой системы в манифесте.

### 3. Какой размер образа hello-world?

По `docker images`: **~25.9 kB** на диске (Disk usage), **~9.49 kB** content size. В `docker inspect` поле `Size` — **16227** байт (~16 kB), это согласуемая оценка «размера» образа в метаданных.

### 4. Что делает команда CMD в hello-world?

`CMD ["/hello"]` задаёт команду по умолчанию: при старте контейнера без другой команды запускается исполняемый файл **`/hello`**, который печатает приветственное сообщение и завершает работу.

### 5. Почему hello-world такой маленький?

Образ содержит почти только статический бинарник/скрипт приветствия и минимальное окружение, **без** полноценной ОС и пакетного набора. Это учебный образ «проверки установки», а не дистрибутив Linux.

### 6. В чём разница между `docker pull` и `docker run`?

- **`docker pull`** — только **скачать** (обновить) образ из реестра в локальное хранилище, контейнер не создаёт и не запускает.
- **`docker run`** — при необходимости **подтянуть** образ, затем **создать** контейнер и **запустить** процесс (команду по умолчанию или указанную вами).

### 7. Где хранятся Docker-образы на вашей системе?

При **Docker Desktop на Windows** движок работает в **Linux-ВМ (WSL 2)**. В `docker info` указано **`Docker Root Dir: /var/lib/docker`** — это путь **внутри** этой Linux-среды. На стороне Windows данные обычно лежат в виртуальном диске WSL (например, дистрибутив `docker-desktop-data`); точный путь на хосте зависит от версии Desktop, но логически всё содержимое образов — под этим корнем в ВМ.

### 8. Что показывает `docker info` о вашей системе?

Сводка о **сервере**: версия Engine, число контейнеров и образов, драйвер хранилища (**overlayfs**), ОС (**Docker Desktop**, **linux/amd64**), ядро **WSL2**, CPU и память, выделенные ВМ, корень данных Docker, сеть, плагины и т.д. Полный вывод — в `docker-info.txt`.

### 9. Сколько контейнеров hello-world в `docker ps -a`?

По сохранённому снимку `docker-containers.txt`: **6** записей с образом `hello-world` / `hello-world:latest`. Число может вырасти после новых запусков; актуальное значение — снова `docker ps -a`.

### 10. Сравнение размеров базовых образов (alpine / ubuntu / busybox)

Эти образы **не устанавливались** в рамках данной работы на Windows. Для сравнения «на пальцах»: **ubuntu** обычно самый тяжёлый (полноценный пользовательский минимум дистрибутива), **alpine** и **busybox** — лёгкие минималистичные базы, **hello-world** — демонстрационный микрообраз.

### Какие образы на машине самые большие и почему?

По `docker-images.txt` среди локальных образов крупнее всего **postgres:17** и **employe-app** — это **СУБД / приложение с зависимостями (JVM, библиотеки)**, а не демо-образ. **hello-world** — наименьший из списка, так как не тянет за собой стек приложения.

## Образ и контейнер (кратко)

- **Образ** — неизменяемый шаблон слоёв файловой системы и метаданных (команда по умолчанию, переменные среды).
- **Контейнер** — запущенный (или остановленный) экземпляр поверх образа с собственным слоем записи и идентификатором; один образ может породить много контейнеров.
